# 工作台视觉与信息层级改造（2026-11-15）

## 判断：这是运维台，不是仪表盘

界面上有 1702 个账号（ChatGPT 1179 / Grok 410 / AWS 58 / Kiro 55），其中
**607 个已封、68 个失效**。用户每天打开它的第一个问题不是「数据长什么样」，
而是 **「现在要紧吗、我该做什么」**。

而改造前的工作台把这个答案拆成四张等权卡片：账号可用性、任务状态、各平台、
状态明细。每张都有数字、都能点，但**没有一处替用户下判断** ——
「607 个已封算不算多」要自己算。

## 已更新的内容（工作树里已有的，我沿用而非推翻）

前一轮已经把配色从苹果蓝暗色改成**苔绿浅色**（`theme.ts` 300 行改动），
方向是对的：绿在这个产品里有语义（可注册 / 可用），不是装饰。
我的改动建立在这个方向上，没有另起炉灶。

## 我做的一处结构性改动：待办横条

在页头下方加一条横条。它不是「又一张卡片」：没有独立白底、没有阴影、
没有卡片圆角，一行结论 + 一条指向。

**唯一引用它修复的三条逻辑**（都在 `src/lib/attention.ts`，纯函数）：

1. **判读优先级**：失败 > 运行中 > 排队 > 补货 > 正常。
   失败排第一，因为它会**静默消耗**邮箱与代理 —— 越晚发现代价越大。
2. **不谎报**：数据没到齐时只说「正在读取」，绝不说「一切正常」。
   这类静默谎报本仓库已经踩过（批量删除失败却弹「已删除」）。
3. **已到手的信息先用**：`/api/tasks` 约 0.5s、`/api/accounts/stats` 要
   3.5–6s，差一个数量级。改造前它等两者都到齐 —— 实测头像右侧已经显示
   「1 个任务正在运行」，横条还说「正在读取」，把已知的事藏起来。
   现在分开传 `tasksLoaded` / `statsLoaded`，任务结论立刻出。

## 视觉词汇

| 元素 | 处理 | 理由 |
|---|---|---|
| 左缘竖线 2px | action 砖红 / active 品牌绿 / watch 琥珀 / clear 透明 | 只用**一个**视觉信号标级别，不铺底色（会像系统告警条）、不放图标（与箭头重复） |
| 结论字号 15px / 500 | 略大于正文 | 它是这一屏唯一的主句 |
| 细节 12px / tabular-nums | 数值不跳动 | 「997 / 共 1702」两段数字要能对齐扫读 |
| 动作 32px 高点击区 | 唯一指向 | 页面上第一个可交互元素，焦点环必须可见 |
| 无进场动画 | 刻意 | 它要人读结论，不是看进场 |

## 顺带修掉的两个真实前端缺陷

都不是设计问题，是**功能缺陷**，改造过程中实测发现：

### 1. 慢接口自取消 → 骨架屏永不消失

`/api/accounts/stats` 实测 3.5–6s。`createDashboardDataLoader.load()` 每次
都 `abort()` 旧请求，而轮询每 15s 一次 —— 只要某次比间隔还慢，新请求就
掐掉还没回来的旧请求，那一半数据**永远不落地**。

Playwright 抓到实证：`('FAILED', 'accounts/stats', 'net::ERR_ABORTED')`。

修法：`loader.isBusy()` 暴露在途状态，轮询看到它就跳过这次。
**保留**「新请求取消旧请求」的既有语义（用户点刷新就该立刻换新，
既有测试也钉着它）—— 不重复发起的责任放在调用方。

实测改善：骨架屏从「20s+ 不消失」变成 **12s 内消失**。

### 2. 横条被慢接口拖住

见上「已到手的信息先用」。实测从「10s 还在正在读取」变成 **4s 出结论**。

## 我刻意没做的

1. **没有重做配色**。既有苔绿方向正确，改动会覆盖上一轮 300 行工作。
2. **没有动其他 11 个页面**。用户说「有些内容已经更新了」—— 我核对过
   工作树有 25 个文件、2001 行未提交改动，那些是别人正在做的。
   我只加了一条横条 + 两个逻辑修复，没有重排别人的页面。
3. **没有引入新字体**。中文用系统 Noto Sans CJK，数字 tabular-nums。
   加 webfont 会让这个内网工具首屏多一次外网请求。
4. **没修 28 个既有 eslint 错误**。不属于本轮范围，混进去会让 review 变糊。
